从作业智能体到学习助手：AI 教育 Agent 的接口融合之路

前几天我写了作业智能体（Homework Agent）的思路——一个能自动识别课程、获取作业列表、辅助提交的 AI Agent 系统。这两天我在推进一个更重要的方向：把作业智能体和我的学习助手进行接口融合。

为什么需要融合？

先说背景。作业智能体目前的核心能力是：

  • 自动识别各课程（概率论、软件工程、大学物理、形势与政策等）
  • 通过超星慕课 API 获取作业列表，识别已完成/未完成状态
  • 模拟请求获取作业题目与答案状态
  • 辅助作业提交

而学习助手负责的是另一件事：

  • 内容理解
  • 知识讲解
  • 答疑解惑

这两个系统各管一摊，但实际上是同一件事的两个阶段。作业智能体负责「采集」，学习助手负责「理解」——割裂开来，两个 Agent 的价值都大打折扣。

融合方案：数据采集 + 知识讲解的闭环

融合后的架构是这样的：

作业智能体层（数据采集）：

  • 识别课程、获取作业列表
  • 将作业题目、答案状态、课程内容等数据采集到统一接口
  • 访问 localhost:3000 的学习助手本地服务，传递数据

学习助手层（内容理解）：

  • 接收作业智能体采集的课程数据
  • 基于超星慕课课程内容进行知识讲解
  • 在用户做作业时提供实时答疑
  • 将答疑结果反馈给作业智能体，辅助自动提交

简单说，作业智能体解决「有什么作业、做没做完」，学习助手解决「这道题怎么做、知识点是什么」。两者通过一个本地接口（localhost:3000）打通，形成一个完整的「采集 → 理解 → 反馈 → 完成」闭环。

这些参数构成了作业智能体与超星慕课通信的基础。学习助手不需要重新解析这些参数——它只需要从作业智能体接收结构化的数据就行。

接口设计

学习助手运行在 localhost:3000，提供 RESTful 接口：

  • GET /courses — 获取课程列表（来自作业智能体）
  • GET /homework/:courseId — 获取某课程的作业列表
  • POST /explain/:questionId — 请求对某道题的讲解
  • POST /answer/:questionId — 提交答案（经用户确认后）

作业智能体作为数据源，定期扫描课程更新，将新作业推送给学习助手，学习助手负责内容层面的处理。

为什么这值得做

这个融合的价值在于：

  1. 效率提升：不再需要手动打开超星、查看作业、再切到学习助手问问题——一切自动化
  2. 知识积累：每次答疑的 Q&A 对可以沉淀下来，形成个人知识库
  3. 逐步进化：从简单的作业管理，到智能学习辅导，再到自适应学习路径规划，这是教育 Agent 的完整进化路径
