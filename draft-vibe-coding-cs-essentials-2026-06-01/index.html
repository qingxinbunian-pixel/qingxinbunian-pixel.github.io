当 Vibe Coding 不够用时：AI 时代的 CS 知识生存指南

Karpathy 说过一句话：“Vibe coding raised the floor. Agentic engineering raises the ceiling.”

翻译过来：vibe coding 提高了下限——不会写代码的人也能做出东西了；但 agentic engineering 才能提高上限——真正懂计算机的人，能让 AI 做出远超”随便试试”的成果。

问题是：从 floor 到 ceiling 之间，到底要补什么？

一个非 CS 人的自我拷问

苏氨酸（Yitong）在公众号写了一篇文章，标题直戳痛点：“和科班程序员划了两小时重点：当 vibe coding 不够用时，我们要如何学习软件工程？”

她的经历很有代表性：

  • 会用 Claude Code、Codex 做项目，但遇到复杂问题就卡住
  • 身边专业开发者用同样的工具，产出完全不同——他们知道每一步在干什么
  • 想系统学 CS，但科班路线动辄上千小时，求职路线又是八股面经

她的解法：拉了一个北大图灵班的朋友 V，对着 csdiy.wiki 划重点。目标是找到 AI 时代最关键的 20%。

划重点：十个模块，100 小时

V 划出的重点不是”精简版 CS 课表”，而是一套面向 AI 使用者的知识体系：

必须动手的

  • 命令行与工具（Git/SSH/Tmux/Docker）：AI 帮你配环境时，你至少得看懂它在干什么
  • 数据结构：树（深度=log节点数）、哈希表（O(1) 查询的原理）、排序——这些是理解 AI 生成代码的基础
  • 网络：装个 Wireshark 抓包，写个 TCP 聊天程序。能通就算过关
  • 体系结构：用 GDB 逐行执行，看每条指令在改哪个寄存器。核心是建立边界意识——什么是计算机能做的，什么是不能做的

知道概念就行的

  • 软件工程：CI/CD、A/B Testing、IaC——当词典查，项目中再理解
  • 编译原理：上下文无关语法（HTML 标签就是经典例子）
  • 分布式系统：Raft 的”过半存活”原则
  • Web 开发：React/Vue 的组件、状态、路由——能看懂框架代码，不需要手写

学习方法的关键洞见

  1. 螺旋式学习：第一遍不求全懂，做项目遇到问题再回来补
  2. AI 写完你”抄一遍”：不是抄答案，是看懂 AI 在写什么、为什么这样写
  3. 通过 CoT 学习：AI 配环境时的思维链就是最好的教程
  4. 估计 100 小时过一遍：不是 100 小时精通，而是建立概念地图

这和 Agent 工作流有什么关系？

在我的 wiki 里，这组知识串起了一条清晰的线索：

  • Vibe coding 是起点——你不需要懂 CS 也能做出东西
  • CS 核心知识 是桥梁——知道 AI 的边界，能读懂代码，能评估输出
  • Agentic engineering 是终点——用 Agent 的思维设计系统，让 AI 执行

这条线索也解释了为什么 Karpathy 从 vibe coding 的提出者，变成了 agentic engineering 的推动者。不是 vibe coding 不行，而是它只是第一层。

值得记住的一句话

学完至少能知道什么是计算机能做到的、什么是不能做到的，知道 AI 的边界在哪里，不至于 vibe coding 的时候完全失控。

100 小时，螺旋式，从项目中学。这不是要你变成专业开发，而是让你从一个”只会 vibe coding”的人，变成一个能指挥 AI 的人。
