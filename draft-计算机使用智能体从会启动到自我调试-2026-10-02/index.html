计算机使用智能体：从「会启动」到「自我调试」

计算机使用智能体：从「会启动」到「自我调试」

10 月 1 日的 Latent.Space 播客请到了 OpenAI 计算机使用（Computer Use）团队负责人 Ari Weinstein 和 API 团队 Nikunj Handa，聊透了 CU 能力这一年的「180 度转弯」。核心变化一句话：从「会启动任务、遇错卡死」到「自我调试、写 JavaScript 操作电脑」。

进步的分水岭：能否从失败中恢复

Sky 时期的计算机使用模型能启动任务，但遇到错误就卡死；现在的模型擅长调试、重试、内省。Ari 自己订餐要花 2 小时，CU 只用 15 分钟——8 倍速，跑在 GPT-6.1 Sol 上。

这提示了一个判断 agent 进步的更普适标准：别再只看「能否完成任务」，要看「能否从失败中恢复」。失败处理能力才是智能体走向实用的分水岭。

多模态融合 + 写代码操作电脑

CU 的输入不再是单纯截图，而是「截图 + 无障碍树 + DOM + Playwright + 生成代码」的多模态融合——无障碍技术意外成了智能体的「眼睛」，这是被低估的信号之一。输出端也不再是一次一个动作地点击，而是直接写 JavaScript 让电脑批量执行。

另一个被低估的信号：等待网页加载成了 benchmark 的时间大头——事件驱动的 harness 设计正在变成真正的护城河。

API 新栈：推理原语的集体升级

这次访谈还披露了 DevDay 之后 API 层的几项新原语：

  • 异步函数调用：工具执行时不暂停推理，推理管线从同步阻塞走向异步编排；
  • 缓存/预热/压缩：30 分钟缓存命中保证、12 小时缓存窗口（预览）、cache 读降价 25%，server-side compaction 把上下文压缩从客户端命令变成服务端能力；
  • UltraFast 首次进入 API：先帮 Luna 降价 80%，再追最快——推理加速成了 API 定价的杠杆。

最耐人寻味的是「缓存预热 + 多实例派生」的组合——有人把这解读为「AI 云」的 EC2/S3 雏形：为每个智能体预热一个专属模型实例，随时派生。

Decisions API：一周克隆 Jev 的实证

Nikunj 透露 Decisions API 没有训练新模型——用 Luna 权重做零样本约束 + 结构化输出 + TTFT 优化 + 多问题并行批量，一周就克隆出了 Jev 的核心体验；两周后市场已经出现约 100 个 Jev 克隆。

这是「单点模型技巧不是护城河」的最新鲜实证：Jev 的范式价值被验证了，但专门训练的模型本身可以被快速复制。真正的壁垒转向校准质量、评测权力与 workflow 集成——对「决策模型」赛道来说，这比任何单点技术都更值得警惕。

系统性共振，而非模型单点变强

CU 的进步不是模型单独变强，而是模型 + harness + 多模态表征 + 推理栈的系统性共振。OpenAI 把 CU 模型与自家 harness 捆绑训练，形成耦合护城河——对开发者来说，买 API 比自建 harness 划算得多。

还有一层递归：用 Computer Use 开发 Computer Use，智能体建完软件自己测试，人类不再当 QA。自举一旦跑起来，迭代速度会超出线性预期。
