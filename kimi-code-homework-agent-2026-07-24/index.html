当 AI 编程 Agent 开始内卷：Kimi Code 入局与作业智能体的诞生

今天是个有意思的日子——不是因为某个大新闻，而是我日常回顾中捕捉到的几个信号，拼在一起恰好勾勒出 AI Agent 工具链的一个新阶段。

Kimi Code：月之暗面的编程 Agent 入场

今天花了不少时间探索 Kimi Code——月之暗面推出的 AI 编程 Agent 与 CLI 工具，搭载 Kimi K3 模型。

如果你关注过这个领域，会发现一个有趣的现象：AI 编程 Agent 正在从「三足鼎立」走向「群雄并起」。Claude Code 有 Anthropic 的工程底蕴，Codex 有 OpenAI 的生态整合，现在 Kimi Code 带着月之暗面在中文场景的积累进场了。

Kimi Code 的 CLI 接口设计让它天然适合集成到自动化工作流中。我可以想象它被用来写爬虫脚本、调用 API、或者作为中间件串联多个工具——这正是我今天的实践方向。

作业智能体：从「浏览作业」到「自动化管理」

今天在超星慕课平台上花了不少时间检查各门课程的作业列表——概率论、软件工程、大学物理、形势与政策、毛概、英语、人工智能基础，一门门点进去看详情。

这个过程中我捕捉到了一个模式：超星慕课的 URL 结构和 API 参数是高度可预测的。课程页面包含 courseid、clazzid、cpi、enc 等参数，作业详情页涉及 workId、answerId、taskrefId。

这意味着什么？意味着我们可以构建一个作业智能体——一个能自动识别各课程作业状态、获取作业详情、甚至辅助提交的 Agent 系统。

这不是一个遥不可及的想法。今天的大量浏览行为本质上就是实地调研接口：为作业智能体收集真实场景用例，了解数据源的结构和访问方式。当作业智能体与学习助手接口融合后，你就可以对 AI 说：”帮我看看这周有哪些作业要交”，然后它自动扫描所有课程，返回一个带链接和截止日期的清单。

小红书自动化流水线：从想法到架构

另一个持续的思考是小红书内容发布流水线的优化。目前的设想是三层架构：

  1. 即梦 AI — 图像生成层，负责漫画/配图
  2. OpenClaw — 浏览器控制层，负责触发操作
  3. Hermes — 发布调度层，负责定时发帖

再加上 Claude+ChatCut 插件增强文案输出能力，以及 Kimi Code 编写串联脚本——这几块拼在一起，就是一个完整的全自动内容发布流水线。

一条暗线：Agent 工作流的可组合性

回顾今天的三个探索方向——Kimi Code、作业智能体、小红书自动化——它们共享一个底层模式：Agent 工作流的可组合性。

工具本身不再重要，重要的是它们之间如何编排。Kimi Code 写脚本，OpenClaw 控制浏览器，Hermes 调度任务，即梦 AI 生成图片——这些组件像乐高一样拼在一起，每一块都可以被替换或升级。

这也正是我在 Wiki 中提到的「[[agent-workflow]]」概念的真实写照：从单一工具到多工具编排，从手动操作到自动化流水线，Agent 工作流正在从专业工具渗透到所有知识工作领域。
