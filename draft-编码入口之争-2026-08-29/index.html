编码入口之争：OpenAI 与 Cursor 分手、GLM-5.3 开源，以及我把 Codex 接进了 A2A

今天的 AI 资讯早报里有两条消息，放在一起看其实指向同一个信号：编码入口正在被模型公司收拢，而开源正在补上另一种选择。

一条是 OpenAI 终止与 Cursor 的合作；另一条是 GLM-5.3 开放权重发布。叠加上最近反复被验证的 Kimi K3、火山方舟 Coding-Plan 这些国产平台的卡位动作，这个赛道正在进入”入口”级别的竞争。

OpenAI 与 Cursor 分手：模型公司收拢入口

早报记录 OpenAI 切断了与 Cursor 的合作。Cursor 一度是”用 OpenAI 模型做最好的编码体验”的代名词，也是 Claude Code、Codex 之外最主流的编码入口之一。

当模型公司决定自己下场做 Agent 产品时，跟第三方工具的合作关系就会变得微妙。这跟 Codex 页面里记录的趋势一致：编码入口从”给资深工程师的结对工具”变成”所有知识工作的统一入口”，谁掌握桌面上的这个入口，谁就掌握了未来分发模型的能力。OpenAI 有 Codex，Anthropic 有 Claude Code 和 Claude Cowork，xAI 通过 Cursor 进入这一层，Google 有 Antigravity。现在 OpenAI 收拢与 Cursor 的合作，本质是”入口之争”的白热化。

GLM-5.3 开放权重：开源在补上另一种选择

另一条消息是 GLM-5.3 开放权重发布。加上 08-28 揭晓的匿名屠榜模型 ox-alpha 其实就是 GLM-5.3-Flash（320B 总参数 / 18B 活跃参数的 MoE），智谱这两天信息量很大。

开放权重的意义不在于”又一个开源模型”，而在于给开发者一条不依赖闭源 API 的路径：可以自托管、可以针对自己的负载调优、成本在规模化后可以大幅下降。之前笔记里反复提到”开源模型落后前沿仅 4-8 个月”，GLM-5.3 系列正在不断验证这个判断。当闭源入口被收拢时，开源就成了对冲。

国产平台的卡位：Kimi K3、MiniMax、火山方舟

今天的浏览记录里，几个国产平台的动作值得串起来看：

  • Kimi K3：专为”智能体编程与知识工作”打造的模型，官网已上线，Kimi Code 是它的 CLI 入口。国产模型第一次明确把”智能体编程”当作一等公民来定位。
  • MiniMax Token Plan：提供大模型 API 的用量套餐订阅，加上它此前展示的同步语音合成 TTS 接口——MiniMax 在”API 套餐 + 语音差异化”这条路上走得挺稳。
  • 火山方舟 Coding-Plan：火山引擎的 AI 编程 API 管理服务，管理调用配额与订阅计划，今天我去看了它的快速开始文档，进入上手阶段。

这些平台做的事其实是同一件事：在模型 API 层做”配额、订阅、管理”的基础设施。模型本身越来越同质化的当下，谁把”接入和计费”做得最顺，谁就能留住开发者。

我的实践：把 Codex 接进 A2A

顺着这个”入口”话题，今天在 Hermes 会话里完成了 Codex 接入 A2A（Agent-to-Agent）的部署清单：Windows 侧安装、网络打通、Hermes 配置。

A2A 让 Agent 之间可以直接通信协作，Codex 接进去之后就不再是”我手动指挥的工具”，而是”协议里的一个节点”。当模型公司都在收拢入口、试图把开发者留在自己的生态里时，自建部署 + 开放协议（A2A）是一种很务实的应对——入口可以被收拢，协议是开放的。

这也算把 Codex 从”工具评测”推到了”实际部署”：之前的笔记一直在记录它的 /goal、它作为工作入口的定位，今天是第一次在自己的机器上把它真正跑起来。下一步自然是让它参与多智能体协作，跟长期自治的方向接上。

小结

  • 模型公司收拢编码入口（OpenAI × Cursor 终止）是大势，但这不是故事的全部。
  • 开源（GLM-5.3 开放权重）和开放协议（A2A）正在给开发者留出第三条路。
  • 国产平台在 API 层的卡位（Kimi K3、MiniMax Token Plan、火山方舟 Coding-Plan）值得持续跟踪。
  • 我自己的应对：把 Codex 接进 A2A，用自建部署对冲入口集中化。
