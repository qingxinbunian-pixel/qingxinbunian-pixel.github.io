DeepSeek DSec：为大规模 Agent 训练打造的沙盒基础设施

当各家实验室还在比拼模型参数与基准分数时，DeepSeek 悄悄把火力对准了 Agent 训练最不起眼、也最烧钱的环节——训练沙盒。9 月底随 DevDay 报道公开的 DSec（DeepSeek 弹性计算），是面向大规模 Agent 强化学习的沙盒基础设施；10 月初的知乎专栏进一步拆解了它的设计思路。这可能是理解中国实验室「RL 自改进」路线的一块关键拼图。

为什么 Agent 训练需要专门的沙盒

大模型训练要的是 GPU 和算力，而 Agent 训练要的远不止这些：智能体要在真实环境里试错——写代码、跑测试、调 API、操作网页，每一步都可能产生不可控的副作用。于是训练平台必须同时提供两样东西：

  1. 隔离：每个智能体实例跑在自己的沙盒里，互不干扰、不污染宿主；
  2. 弹性：试错是海量并发的，单分片每天要能扛住数百万次沙箱的创建与销毁。

DSec 解决的问题正是「让隔离环境像容器一样廉价、像云计算一样弹性」。

DSec 的四类后端

据公开信息，DSec 提供四类后端：

  • AgentGym — 面向通用智能体训练的 gym 环境
  • MinimalDSec — 最小化沙箱实现，主打轻量与快速拉起
  • DeepSWE — 软件工程（SWE）任务环境，与自主 Agent 基准直接挂钩
  • general-task-environment — 通用任务环境

四类后端覆盖了从「代码任务」到「通用任务」的谱系，说明 DeepSeek 没有把沙盒当成单一工具，而是当成一套可组合的基础设施层。

关键指标：>50 倍超卖，单分片每天约 300 万沙箱

最震撼的数字在这里：超过 50 倍的超卖（overselling），单分片每天可运行约 300 万个沙箱。

超卖是云计算的经典手段——赌用户不会同时用满资源。但把超卖做到 50 倍以上、且用于训练场景，意味着 DeepSeek 对沙盒的资源复用效率做了极深优化。300 万沙箱/天的量级也说明：Agent RL 训练的真实规模，已经远超大多数人「开几个容器跑实验」的想象。

与「RL 自改进」路线一脉相承

DSec 不是孤立的工程产物。它和 [[You-Only-RL-Once（单次混合RL）|小米 MiMo 的单次混合 RL]] 路线共享同一个底层信念：中国实验室在算力受限下，用「RL 自改进」对冲规模劣势。MiMo 用约 $2.6M 训出开源最强模型，靠的是把 RL 做深；DeepSeek 则把 RL 的基础设施做厚——沙盒越便宜，Agent 就能试越多错，模型就能从试错中学到越多。

顺带一提，DeepSWE 后端对应的正是 DeepSeek V4.1 Flash 在自主 Agent 基准（DeepSWE 74.2）上领先的领域——沙盒基础设施与模型能力在这里形成了闭环。

启示

  1. Agent 训练的基础设施战已经开打。当模型层趋同，谁能把「让 Agent 廉价试错」的工程做到极致，谁就拥有下一阶段的训练优势。
  2. 沙盒正在成为新的战略资产。OpenAI 的计算机使用智能体、DeepSeek 的 DSec、小米的 YORO——各家的 Agent 路线最终都要落到「环境」这个地基上。
  3. 对个人开发者：DSec 的公开资料是理解「生产级 Agent 训练环境长什么样」的好教材——隔离、弹性、超卖、后端可组合，这些设计词同样适用于你自己的 Agent 项目架构。
