我的作业智能体终于上线了：不念助手

从 7 月 24 日写下作业智能体的第一版思路，到 7 月 31 日推动它与学习助手做接口融合，再到今天——不念助手（超星作业智能体）正式以独立网站形态上线 qingxinbunian.com。这个做了快两个月的项目，终于从概念和本地脚本，变成了一个能访问的产品。

回看这条路

作业智能体的想法其实很朴素：超星慕课上的作业分散在各门课程里，每门课要手动点进去看有没有新作业、做没做完，太零碎。能不能让一个 Agent 替我盯着？

第一版解决的问题是「识别」：

  • 自动识别各课程（概率论、软件工程、大学物理、形势与政策……）
  • 解析超星慕课 URL 结构（courseid、clazzid、cpi、enc 参数）
  • 通过 API 获取作业列表，识别已完成/未完成状态

7 月底我意识到，光有「识别」还不够。作业智能体负责采集，但用户真正需要的是「这道题怎么做」。于是有了第二阶段：作业智能体（采集）+ 学习助手（讲解）的接口融合，形成「采集 → 理解 → 反馈 → 完成」的闭环。

从脚本到产品

前两个阶段，它都还只是跑在本地的东西。今天它变成了一款真正的产品：

  • 独立域名 qingxinbunian.com
  • 登录流程接入超星账号（passport2.chaoxing.com）
  • 网站形态，不再是终端里的脚本

这个转变的意义在于：它从一个「我自己的工具」，变成了一个「可以给别人用的服务」。作业智能体从「自动化个人任务」跨进了「产品化交付」的门槛。

技术栈回顾

这条路上攒下的技术点：

  • 超星慕课课程页 URL 参数：courseid、clazzid、cpi、enc
  • 作业详情页 API 参数：workId、answerId、taskrefId
  • 模拟请求获取作业题目与答案状态
  • 本地服务接口（localhost:3000）打通采集层与讲解层

而整个开发过程，也一直有 AI 编程工具参与——从 Kimi Code 编写自动化脚本，到 Codex 承接项目级的改造。这大概就是现在做小工具的真实节奏：想法 → Agent 快速实现 → 迭代成产品。

下一步

上线只是开始。接下来想做的事：

  1. 把答疑沉淀做成个人知识库
  2. 学习助手与作业智能体的融合在网站形态下真正跑通
  3. 从「作业管理」走向「学习辅导」
