从Vibe Coding到Loopcraft：AI工程的三次范式跃迁

从Vibe Coding到Loopcraft：AI工程的三次范式跃迁

2026年，AI工程正经历一条清晰的演进路径：从逐条提示，到声明终点，再到设计循环。这不是概念炒作——Recursive SI和微软Arbor已在真实基准上产出SOTA结果，DiffusionGemma让推理成本骤降4倍，而Claude Fable 5的静默降级事件则暴露了一个更深层的问题：你不能信任任何一个模型提供商的行为稳定性。

这条演进路径有三个清晰的阶段，每个阶段解决的核心问题不同。

第一阶段：Vibe Coding——“许愿池”时代

Karpathy在2025年初提出的概念：不深入理解代码逻辑，靠直觉和AI辅助写代码。你说一句，它写一段；你说”有bug”，它改一轮；你说”继续”，它再写一段。

刘小排的描述更精准：你只不过把AI当成了一个许愿池。

Vibe Coding适合探索和小活儿，但任务一长，你就变成了陪AI加班的人。核心瓶颈：人的注意力和时间。

第二阶段：Goal Coding——声明终点

2026年5月，OpenAI的Codex和Anthropic的Claude Code几乎同时推出/goal命令，范式开始转换。

过去你告诉AI”做下一步”。现在你告诉它终点在哪：

把checkout的p95延迟压到120ms以下，跑通基准测试，现有功能不许回归。

然后你合上电脑，去喝咖啡。它自己规划、自己写、自己测、发现不对自己修——循环到你定义的终点被达成为止。

两个实现有微妙差异：

  • Claude Code /goal：声明式验收，小模型当裁判，达标自动停——像请了个实习生
  • Codex /goal：持久thread state，pause/resume/clear，预算管控——像配了个项目经理

核心能力转变：从写prompt到定义”什么叫做完”。

第三阶段：Loopcraft——循环堆叠

这是最新的范式迁移，焦点从”哪个模型最强”转向”谁来编排循环”。

Loopcraft的核心洞察：人类逐条提示智能体是系统瓶颈，真正的杠杆在于设计自运行的循环架构。这不仅是Goal Coding的延伸——Goal Coding解决”如何定义完成”，Loopcraft解决”如何让循环持续可靠运行”。

维度 传统提示 Goal Coding Loopcraft
交互模式 一问一答 声明终点 设计循环架构
人的角色 逐步指挥 目标设定+验收 架构设计，退出内层循环
扩展瓶颈 人注意力 单目标验收 循环可靠性

咸教训：Loopcraft的理论基石

Rich Sutton的苦教训（Bitter Lesson）指出：随算力扩展的通用方法终胜人工知识。2026年提出的”咸教训”（Salty Lesson）将其翻译到智能体域：别亲手修东西，构建随智能体数量扩展的目标-编排系统。

咸教训比苦教训更精妙的地方在于：它是双向的。早期下沉一层循环可获得可靠性，后期上浮一层循环可获取杠杆。

但这里有个被回避的核心矛盾：上浮循环的前提是底层循环可信。SciConBench显示前沿智能体在专家综合任务上得零分，Agents’ Last Exam在最难层级同样归零。告诉人们”爬上去”的忠告，仅在你脚下的梯子不会断时成立。

循环正在变便宜

Loopcraft之所以在2026年成为可行方向，不仅因为范式认知成熟，更因为循环的成本在快速下降：

  • DiffusionGemma：DeepMind将扩散与Gemma 4架构融合，推理速度比同系列快4倍——循环每轮迭代成本大幅下降
  • Unsloth Gemma 4 MTP GGUFs：本地推理提速1.4-2.2倍——降低对云端API的依赖
  • Recursive SI：在三个公开基准上达成SOTA，证明窄域高反馈循环已可产出实际成果
  • 微软Arbor：持久化假设树精炼，声称六项研究任务超越Codex和Claude Code

循环越便宜，堆叠越可行。这是经济学原理在AI工程中的直接体现。

静默降级：循环架构的反面约束

就在循环架构理论走向成熟的同时，一个现实问题给了所有人当头一棒：Anthropic悄悄削弱了Claude Fable 5在AI研究场景的能力。

被曝光后一天内回退。争议焦点不是”该不该有安全护栏”，而是护栏是否可以不透明。安全措施正常，但暗中进行能力削减违反用户-提供商契约。

工程启示来自Gergely Orosz：在模型调用之上建提供商无关的路由层。如果提供商可以一夜之间静默改行为，你的应用质量就在你零行代码变更的情况下退化——连个弃用通知都没有。

这不是治理故事，是工程刚需。对Loopcraft来说，这意味着自治系统必须设计提供商故障的容错机制：

  1. 提供商无关的路由层
  2. 后备模型温备
  3. 输出质量持续仪表盘
  4. 基准测试自动化

被低估的工程信号

除了核心范式，Loopcraft讨论中还有几个值得长线关注的信号：

凭证隔离成为架构模式：Claude Managed Agents在网络边界交换凭证，智能体永远看不到密钥本身。这应是所有智能体系统的默认模式，而非特例。

自动审查成为默认：Cursor将自动审查作为默认行为，分类器子智能体做动作门控。当循环自主运行时，审查层不是可选的，而是必要条件。

记忆管理转向主动维护：Weaviate的Engram提出”提取-转换-提交”循环替代简单追加聊天日志。更大的上下文窗口并没有杀死检索——因为上下文仍有延迟和成本。

模型供应链的隐蔽复杂度：AllenAI的ModSleuth揭示，Olmo 3依赖89个模型和183个数据集，Nemotron 3依赖273个模型和560个数据集。溯源信任问题堪比软件供应链危机，但几乎无人讨论。

我的判断

Loopcraft的方向是对的，但当前叙事过于乐观。

循环堆叠是正确的长期赌注，但2026年的现实是：大多数团队连一个可靠运行24小时无需人工干预的循环都搭不出来。 智能体在有界高反馈循环中有效，在专家综合上归零。

我的建议是：先投资无聊的基础设施——可观测性、回滚、凭证隔离、自动审查——再谈向上堆叠。没有可靠底层循环的Loopcraft，不是艺术，是赌博。
