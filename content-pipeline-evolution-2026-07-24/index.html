从生图到发布：我的 AI 内容创作流水线进化记

今天在整理思路时，发现我的内容创作流水线正在经历一场有趣的进化——从单一工具到多工具编排，从手动操作到全自动流水线。这条线清晰地勾勒出了三个阶段的递进。

第一阶段：即梦 AI + Hermes 的生图发布

基础能力已经跑通——即梦 AI 负责生成图片，Hermes 负责定时发布到小红书。这套组合能独立完成「生图 → 发布」的闭环，但缺少两个关键环节：文案创作和浏览器交互。

第二阶段：Claude + ChatCut 加入文案增强

Claude 配合 ChatCut 插件的加入填补了文案的短板。ChatCut 增强了 Claude 的截图/代码识别能力，让 Claude 能更好地理解页面上下文，生成更精准的文案和配图逻辑。

这个组合让流水线变成了：即梦 AI 生图 → Claude+ChatCut 写文案 → Hermes 发布。但问题来了——三块之间的串联还是手动的，需要一个”胶水层”把它们粘在一起。

第三阶段（进行中）：全自动漫画发布流水线

这就是下一阶段的目标——全自动，从创作到发布零人工介入。

架构设想是四层：

  1. 即梦 AI — 图像生成层，负责漫画分镜/配图
  2. OpenClaw — 浏览器控制层，负责自动化操作
  3. Kimi Code — 脚本编写层，负责串联各组件
  4. Hermes — 发布调度层，负责定时发帖

关键洞察是：工具本身不再重要，重要的是它们之间如何编排。Kimi Code 写脚本调用即梦 AI 接口，OpenClaw 控制浏览器完成交互，Hermes 调度任务——这些组件像乐高一样拼在一起，每一块都可以被替换或升级。

另一条线：作业智能体与学习助手

除了内容创作，另一个并行推进的项目是作业智能体与学习助手的接口融合。今天大量浏览超星慕课课程作业的行为，本质上就是在为这个接口做实地调研。

这里有一个有意思的分工模型：

  • 作业智能体负责「操作层」——识别课程、获取作业列表、模拟提交
  • 学习助手负责「理解层」——内容讲解、答疑、知识梳理

两者融合后，你只需要说一句「帮我看看这周有什么作业要交」，作业智能体自动扫描所有课程返回清单，学习助手再针对每一项作业给出辅导。这背后的逻辑和内容创作流水线是一样的——分层解耦，各司其职。

一条暗线：Agent 工作流的可组合性

回顾今天的两个方向——内容创作流水线和作业智能体——它们共享一个底层模式：Agent 工作流的可组合性。

这不是一个抽象的概念。今天在 Kimi Code 上花的时间、在超星慕课上浏览的每一个课程页面、在 GitHub 上看的每一个仓库，都在为这个模式积累原材料。当流水线跑通的那一天，回头看会发现——每一步都是必要的铺垫。
